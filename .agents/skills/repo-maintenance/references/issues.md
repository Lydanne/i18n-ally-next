# Issue workflow

1. List open issues separately from PRs, including pagination, and classify bugs first. Read the report, comments, environment and reproduction. Search existing code, tests, history and open PRs for the same defect; do not rely on labels or linked-issue text alone.
2. Reproduce or otherwise establish the problem from evidence. If an existing PR actually fixes it, review and handle that PR under the PR workflow. Otherwise implement a focused fix on an appropriate branch, add a meaningful regression test, run relevant checks and submit a PR. Link the issue in the PR and ensure the final issue state reflects the merged result.
3. If essential information is missing and investigation cannot proceed, comment with the precise missing reproduction, versions, logs or expected behavior, then close the issue with an appropriate reason and explicitly invite the reporter to reopen after supplying it. Redact sensitive data. For duplicates, already-fixed reports or unsupported requests, explain the evidence and close with the appropriate reason rather than claiming a new fix.
4. Complete each in-scope issue when feasible. If a reproducible bug cannot safely be fixed or an external action is blocked, report the blocker rather than closing it as completed. Recheck whether merging a PR actually closed the linked issue; close manually when justified and authorized.
